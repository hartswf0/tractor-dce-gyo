Studio Tutorial
ONYX Studio
One constellation: Head / Abs / Tail, Brick Branch, Brick Architect, and LGI Brickbender. A shared ONYX SceneCollection on a 9×9 grid.
Studio shell
onyx-studio.html hosts all tools as tabs.
Switch views without changing data.
Optional split mode: Head + Tail side by side.
Use cases
Ingest scenes from LEGOS or JSON once.
Read the story as narrative, as code, and as GS2P.
Present the same system in multiple visual grammars.
The Constellation
Six tools orbiting a single ONYX SceneCollection.
Narrative tools
Head – narrative entities, scenes, forks, timeline.
Tail – story system backplane: goals, obstacles, morphisms.
Abs – ingest + abstraction; owns the SceneCollection.
Grid / GS2P tools
Brick Branch – 9×9 multimodal core, branches, sonified flow.
Brick Architect – 9×9 structure and dependencies, with minimap.
LGI Brickbender – GS2P mapper: ground / site / sky / perspective.
The studio shell is only a frame; ONYX Abs and localStorage['onyx_scene_collection'] bind the constellation.
Data Model · SceneCollection
One canonical object feeding all ONYX views.
Core objects
SceneCollection – { version, scenes[] }.
Scene – grid of cells with kind, label, relations.
Cell – an entity or beat living at [row, col] on the 9×9.
Persistence
ONYX Abs converts LEGOS / JSON into a SceneCollection.
Abs caches it to localStorage['onyx_scene_collection'].
Head, Tail, Branch, Architect, and GS2P all read from that key.
Contract localStorage['onyx_scene_collection'] = SceneCollection
Flow 1 · Ingest & Narrative Views
From LEGOS JSON to ONYX Head and Tail.
  1. Open onyx-studio.html and choose the ABS tab.
  2. Load a LEGOS multi-channel export or ONYX SceneCollection JSON.
  3. Confirm scenes via the Abs scene picker and autoplay controls.
  4. Switch to HEAD – walk scenes as narrative beats with entities and forks.
  5. Switch to TAIL – inspect the story as a system of goals, obstacles, and morphisms.
Abs knows about the file format. Head and Tail only know about scenes and entities.
Flow 2 · ONYX to 9×9 Grids
Project ONYX scenes into Brick Branch and Brick Architect.
Brick Branch
Reads onyx_scene_collection via importOnyxSceneFromCollection().
Renders an ONYX scene as a 9×9 grid with block types.
Lets you branch, sonify, and navigate upstream/downstream calls.
Brick Architect
Uses a similar import path from the shared SceneCollection.
Emphasizes structure: callers, deps, and wire diagrams.
Minimap and x-ray navigation across the source.
Same scenes, new grammar: ONYX grid → code / dependency space.
Flow 3 · ONYX to GS2P
Mapping stories into ground / site / sky / perspective.
Import
LGI Brickbender reads onyx_scene_collection via Import ONYX.
Flattens the 9×9 ONYX grid into a set of nodes.
Auto-maps ONYX kinds to GS2P kinds, e.g.:
  • location / scene → site
  • goal / obstacle / shift / timepoint / morphism → sky
  • story → perspective
  • everything else → ground
Edit
Drag nodes to lay out flows, sites, and constraints.
Retag nodes between GS2P layers as needed.
Export JSON as a portable LGI map of the ONYX story/system.
