ONYX STUDIO Tutorial · Research Olog

How the ONYX Studio constellation fits together: Head / Abs / Tail, Brick Branch, Brick Architect, and LGI Brickbender as one narrative grid for scenes, code, and GS2P maps.
Launch ONYX Studio Head Abs Tail Branch Architect GS2P

1 · Overview

ONYX Studio is a multi-tool shell for working with stories and systems on a 9×9 grid. It connects:

  • ONYX Head / Abs / Tail – narrative entity + scene tools.
  • Brick Branch / Brick Architect – 9×9 code / dependency explorers that can import ONYX scenes.
  • LGI Brickbender – a GS2P mapper that turns ONYX grids into ground / site / sky / perspective maps.

This page is a tutorial + research olog that explains how the ONYX Studio pieces relate, the shared data model, and concrete step-by-step flows you can follow.

Quick start: open onyx-studio.html, use the ABS tab to load a LEGOS multi-channel or SceneCollection JSON, then explore the same scenes through HEAD, TAIL, BRANCH, ARCH, and GS2P.

2 · Components (Docked Tools)

Each tool is a separate HTML surface but ONYX Studio docks them together and lets them share a SceneCollection.

Studio Shell
onyx-studio.html

The tab strip + frame shell that hosts all ONYX tools. Tabs: HEAD · ABS · TAIL · BRANCH · ARCH · GS2P.

Layout Frame switcher Split mode (Head + Tail)

Use this page as your primary entry point. It never owns data; it just frames other tools.

ONYX Head
onyx-head.html

A narrative entity & timeline view for ONYX scenes. Sidebar shows story info, entity palette, registry, and help.

Timeline Entities Forks

Use Head when you want to think in scenes, entities, and beats rather than code.

ONYX Abs
onyx-abs.html

The ingest + abstraction tool for ONYX. It:

  • Reads LEGOS multi-channel or SceneCollection JSON.
  • Converts it into an internal sceneCollection.
  • Persists that into localStorage['onyx_scene_collection'].
Ingest Scene picker Autoplay

Abs is the source of truth for ONYX scenes. Other tools read from its SceneCollection.

ONYX Tail
onyx-tail.html

A storytelling backplane for ONYX with themable panels, console, and inspector. It speaks the same entity/scene language as Head, but focuses on story system diagnostics.

Story system Inspector Console

Use Tail to debug and tune the machinery behind a story: goals, obstacles, morphisms.

Brick Branch
brick-branch.html

A 9×9 multimodal core for exploring code / scenes as a grid. It can:

  • Parse code into 81 cells with functions / variables / tags / control.
  • Import an ONYX SceneCollection from localStorage via importOnyxSceneFromCollection.
  • Let you branch and compare different scene views.
9×9 grid Branching Sonify / haptics

Use Branch to feel the dependency graph of an ONYX scene as a playable grid.

Brick Architect
brick-architect.html

A 9×9 architecture visualizer that can also import ONYX scenes from onyx_scene_collection. It renders scenes as blocks and wires, optimized for structure.

Architecture Upstream / downstream Minimap

Use Architect when you want to see who calls whom and how responsibilities are arranged.

LGI Brickbender (GS2P)
lgi-brickbender.html

A node editor that maps ONYX or arbitrary code into GS2P layers: ground / site / sky / perspective.

  • Can ingest raw code and infer GS2P roles.
  • Can import ONYX scenes from onyx_scene_collection.
  • Lets you arrange nodes and export JSON specs.
GS2P Node editor ONYX import

Use Brickbender to re-express an ONYX story as an LGI map of flows, sites, risks, and views.

3 · Core Workflows

The tools are loosely coupled. The main bridge is a shared SceneCollection in localStorage under the key onyx_scene_collection.

Flow 1
From LEGOS JSON to ONYX Head / Tail
  1. Open onyx-studio.html and select the ABS tab.
  2. In ONYX Abs, choose JSON ingest and load a LEGOS multi-channel or SceneCollection file.
  3. Abs converts it into a sceneCollection and writes it to localStorage['onyx_scene_collection'].
  4. Switch to HEAD and TAIL tabs to view and debug the same scenes.

Abs is the only place that needs to know about the raw JSON format; Head/Tail work on the normalized scenes.

Flow 2
From ONYX Scenes to Brick Branch / Architect
  1. After Flow 1, the browser already has onyx_scene_collection in localStorage.
  2. Switch to the BRANCH tab in ONYX Studio (frame: brick-branch.html).
  3. Use its ONYX import controls (backed by importOnyxSceneFromCollection()) to pull in a scene.
  4. Explore the 9×9 grid: focus one cell, inspect upstream / downstream, and create branches.
  5. Optionally, open ARCH and import the same collection to see a more structural view.

Branch and Architect read from the same SceneCollection but project it into different visual grammars.

Flow 3
From ONYX Scenes to GS2P (LGI Brickbender)
  1. Ensure ONYX Abs has written a SceneCollection for your current story.
  2. Switch to the GS2P tab (frame: lgi-brickbender.html).
  3. Click Import ONYX to read onyx_scene_collection from localStorage.
  4. Brickbender maps ONYX kinds to GS2P kinds via mapOnyxKindToGS2P and lays out nodes.
  5. Drag nodes, adjust kinds, and export JSON to capture the GS2P view of your story/system.

This flow turns the ONYX grid into an LGI architecture map—a different but related olog.

4 · Guided Session: First ONYX Studio Run

A concrete walkthrough using all six tools in one sitting.

Step 0 · Setup

  • Open onyx-studio.html in a modern desktop browser.
  • Confirm that the tab strip shows HEAD · ABS · TAIL · BRANCH · ARCH · GS2P.

Step 1 · Ingest a Scene Collection (ABS)

  1. Click the ABS tab.
  2. Paste or upload a LEGOS export (multi-channel JSON) or an existing ONYX SceneCollection.
  3. Use the scene picker in Abs to confirm that scenes and beats loaded correctly.

Behind the scenes, Abs normalizes the input and writes a sceneCollection into localStorage['onyx_scene_collection'] so other tools can reuse it.

Step 2 · Read the Story Front (HEAD)

  1. Switch to the HEAD tab.
  2. Set a story title and description in the Story Info panel.
  3. Click through the timeline and grid views to see entities moving across scenes.
  4. Use the entity palette to highlight appearances across your story.

Step 3 · Inspect the System Backplane (TAIL)

  1. Switch to the TAIL tab.
  2. Use the Tail UI to surface goals, obstacles, morphisms, or other story mechanics.
  3. Notice how Head and Tail are two projections of the same underlying scenes.

Step 4 · Enter the 9×9 Grid (BRANCH & ARCH)

  1. Switch to the BRANCH tab.
  2. Import an ONYX scene (via its ONYX import controls).
  3. Hover or click blocks to see upstream / downstream relationships and sonified flows.
  4. Create a branch instance from a focused block and compare it with the root view.
  5. Switch to ARCH and import the same SceneCollection to see a structural grid + wires view.

Step 5 · Map to GS2P (LGI Brickbender)

  1. Switch to the GS2P tab.
  2. Click Import ONYX to pull in the first ONYX scene as a grid of nodes.
  3. Check how kinds were auto-mapped:
    • location / scene → site
    • goal / obstacle / shift / timepoint / morphism → sky
    • story → perspective
    • Everything else → ground
  4. Drag nodes into a layout that makes sense for your system.
  5. Export JSON to snapshot the GS2P map of this story.
End state: you now have one story flowing through Head / Tail / Branch / Architect / GS2P, all fed by the same ONYX SceneCollection created in Abs.

5 · Research Olog Notes

Conceptually, ONYX Studio is a TRUBADOR-style studio that focuses on narrative grids rather than MPD / GOLD. Its olog looks roughly like:

Objects
  • SceneCollection – a set of ONYX scenes with grids and entities.
  • Scene – a 9×9 grid of cells with kind, label, and relations.
  • View – any surface that renders a SceneCollection (Head, Tail, Branch, Architect, GS2P).
Morphisms
  • Ingest: LEGOS / JSON → SceneCollection (Abs).
  • Project: SceneCollection → narrative view (Head/Tail).
  • Gridify: Scene → 9×9 grid with code / dependency semantics (Branch / Architect).
  • MapGS2P: Scene → GS2P node map (Brickbender).

In category-language: ONYX Studio keeps one central object (SceneCollection) and explores many functors out of it into different visual / analytical categories.

Relationship to Other Studios

Compared to HOMER Studio (documented in HOMER-STUDIO-OLOG.md):

  • HOMER wraps Swiss / Frank / Courage / Weaver / WERE / MASTER / MENTO around MPD + GOLD flows.
  • ONYX Studio wraps Head / Abs / Tail / Brick / GS2P around SceneCollection + ONYX grids.
  • HOMER is geometry- and MPD-centric; ONYX is scene- and narrative-grid-centric, but they share the idea of a studio shell + shared bus/state.

Future work for ONYX Studio might include:

  • Adding a bus alongside localStorage so views can react live to each other.
  • Exporting ONYX scenes back into other studios (e.g., sending GS2P maps into a TIMBER or HOMER loop).
  • Documenting a more formal ONYX ontology (kinds, relations, and contracts) parallel to the MPD/GOLD olog.
