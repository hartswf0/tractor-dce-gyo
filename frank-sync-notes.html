1 · FRANK's Job in TRUBADOR

FRANK is the grid and the switchboard. It shows INBOX bricks, 9×9 layouts, and family views for scenes, then points those scenes at a studio (Courage, COOL, HOMER, etc.). To feel alive it needs to know which MPD + GOLD is "current" and where that scene is being edited right now.

2 · Contracts FRANK Cares About

FRANK does not need to render studs or parse every LDraw line; it only needs a few stable signals:

  • Scene identity – a scene key or path from SWISS (e.g. a story id).
  • MPD presence – whether there is an MPD loaded for that scene.
  • GOLD presence – whether Red Bull / Ontology Weaver have emitted GOLD.
  • Where editing lives – which studio owns the live editor (Courage, COOL, HOMER, etc.).

All of these can be sent over the wag-frank bus as small JSON messages, with FRANK listening and patching its grid / cards when things change.

3 · The wag-frank Bus

The wag-frank bus is already used by Courage and the Ontology Weaver. FRANK can treat it as a presence bus:

Existing usage
  • new BroadcastChannel('wag-frank') in Courage / Weaver.
  • Courage emits kind: 'redbull-gold' with GOLD snapshots.
  • Weaver can emit kind: 'weaver-gold' after ontology passes.
FRANK's new view
  • Treat each GOLD emission as a signal that a scene is "alive".
  • Add a small 'scene-updated' contract that HOMER or other shells can emit.
  • Use it to bump INBOX tiles, badges, and family layouts without reloading the page.
4 · Scene-Updated Contract

A shell like HOMER can publish a tiny scene descriptor every time MPD or GOLD changes. This does not replace GOLD; it just advertises that a new snapshot exists.

// BroadcastChannel('wag-frank') message shape { kind: 'scene-updated', source: 'homer', // who is emitting: 'homer', 'timber', 'cool-timber', ... sceneId: 'story/001', // swiss key or path mpdHash: 'abc123...', // optional hash / fingerprint of the MPD text hasGold: true, // whether GOLD exists for this scene studio: 'COURAGE', // primary editor surface updatedAt: 1732400000000 // Date.now() }

FRANK does not need to trust the hash implementation; it just uses mpdHash as a change token. If it changes, FRANK knows the scene moved.

Shell side (HOMER)
const frankBus = new BroadcastChannel('wag-frank'); function publishSceneUpdate({ sceneId, mpd, hasGold, studio, source }) { const mpdHash = simpleHash(mpd); // implementation is shell-specific frankBus.postMessage({ kind: 'scene-updated', source, sceneId, mpdHash, hasGold, studio, updatedAt: Date.now(), }); }
FRANK side
const bus = new BroadcastChannel('wag-frank'); bus.onmessage = (event) => { const msg = event.data; if (!msg || msg.kind !== 'scene-updated') return; // 1) Locate the scene tile / family card by msg.sceneId // 2) Mark it as "live" (badge, highlight, timestamp) // 3) Optionally re-compute derived layout state };
5 · Sync from Courage · Request / Response

Sometimes FRANK should be able to pull the latest MPD / GOLD on demand (for example a "Sync from Courage" button in the grid UI). That path runs through the studio shell (HOMER, TIMBER, etc.) via postMessage.

FRANK → Shell
// Running inside a shell iframe function requestCurrentScene(sceneId) { window.parent.postMessage({ type: 'frank-request-current-mpd', sceneId, }, '*'); }

FRANK can call this when the user clicks a "Sync" action on a tile. The shell is responsible for answering.

Shell → FRANK
// In HOMER or another studio shell window.addEventListener('message', (event) => { const msg = event.data; if (!msg || msg.type !== 'frank-request-current-mpd') return; const { sceneId } = msg; const mpd = getCurrentMpdForScene(sceneId); // e.g. from Courage iframe const gold = getCurrentGoldForScene(sceneId) || null; event.source.postMessage({ type: 'frank-current-mpd', sceneId, mpd, gold, }, event.origin || '*'); });

The implementation of getCurrentMpdForScene is up to the shell. In HOMER it would typically ask the Courage iframe via its own postMessage API.

On the FRANK side, handling 'frank-current-mpd' means updating any local cache and bumping the scene's status to "synced".

6 · Wiring Plan · FRANK + HOMER

With these contracts in place, keeping FRANK live with HOMER becomes a matter of wiring:

  • In HOMER – publish scene-updated after every MPD export from WERE / MASTER and after GOLD emissions from Courage / Weaver.
  • In FRANK – subscribe to scene-updated on the wag-frank bus and update tiles / families in place.
  • Optional pull – expose a "Sync from Courage" action in FRANK that uses the frank-request-current-mpd / frank-current-mpd handshake through HOMER.

This page is a spec surface, not an implementation. HOMER's field notes describe how the shell currently routes GOLD and MPD; these FRANK notes describe how the grid can listen in without owning any heavy 3D code.
