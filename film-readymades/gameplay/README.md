# Play, observe, replay

Open `../production/Film-Butter-Readymades.html`, choose Green Grocer and **Play**. Move with the left joystick or WASD; look with the right joystick. The context button (or E) collects an item in reach and visible around the crate. Collect the native bananas, croissant and carrots, then return to the left-hand register. Checkout produces a game receipt, not a purchase. Replay uses the accepted movement and transaction journal. Save run exports it as JSON.

**Two players:** expand “Two players · Maggie detective” and choose Invite Maggie. The host owns the basket. The guest follows as Maggie and writes an independent notebook. The notebook can be wrong or incomplete. Nearby unobstructed pickups appear as witnessed events; the receipt is revealed after checkout. Guest purchase requests are rejected. Disconnect does not erase the host's basket.

The bundled PeerJS client is 1.5.5; QR generation uses qrcode-generator 1.4.4. Both are vendored with their original headers. PeerJS's default signaling service requires network access. A reachable HTTPS deployment is necessary for phone invitations; the UI does not generate a misleading QR for file or localhost URLs. A custom signaling server may be supplied as `window.FilmPeerOptions` before initialization. Tests use the official `peer` 1.0.2 server with local-only ICE configuration. This is not evidence of cellular-network or TURN interoperability.

**LLM tools:** `ShopOperators.observe()` returns the current role's observation. `ShopOperators.act({verb, target, reason})` accepts `go`, `collect`, `checkout`, `look`, `wait` for the shopper; `follow`, `note`, `undo`, `look`, `wait` for the detective. Reasons are short public action annotations, not hidden reasoning. `go` and `follow` invoke a deterministic pathfinding tool whose movement is checked by the same collision function as joystick input. An LLM chooses the destination and actions; the navigator supplies locomotion. No API key is embedded. A model runner must call these tools; an available tool interface alone does not constitute an LLM playthrough.

`operator-bridge.cjs` is the local two-browser test harness. `operator_cli.py ROLE observe` and `operator_cli.py ROLE act '{"verb":"...","reason":"..."}'` communicate through role-scoped request/reply files. The harness preserves actual commands, results, witnesses and notes. It is a test runner, not a production agent service.

Collision scope: a radius-13, height-52 game envelope uses native leaf bounds, swept in at most 2-unit increments. Stock pickup is an inventory transfer, not an animated hand grasp. Neither the playable level nor the diagnostic reports validate LEGO connections, support, insertion order or physical stability. The older hand-choreographed take remains separately blocked by its contact gate.
