Step 3 · How ONYX reads it
Help · pipeline

The same JSON powers ONYX Abs, Block Merge, and ONYX Tail. You only need to get the shape right.

legos-multi-channel.json
⇢
ONYX Abs · Paste in ingest box
⇢
APP.LEGOS.multiChannelToSceneCollection()
⇢
SceneCollection.scenes[]
⇢
Shared via localStorage (onyx_scene_collection)
  • If JSON has channels[], ONYX converts it to a SceneCollection object.
  • Each channel becomes one scene in the collection.
  • channel.messages[] become scene.beats[] (Scene / Narration / Instruction).
  • channel.grid becomes a 9d79 array of cells that ONYX Tail turns into cubes on the grid.
Quick reference · keys that matter
Schema slice
{
  "channels": [
    {
      "id": "string",          // required – stable id per channel
      "name": "string",        // human label, shown in lists
      "scenario": "string?",   // optional story / project id
      "channelColor": "#RRGGBB?", // optional accent color
      "symbolicId": "string?", // optional external id
      "ringBinding": "string?",// optional bus / ring id

      "messages": [             // time-ordered transcript
        { "id": "M0001", "role": "system|user|assistant", "text": "..." }
      ],

      "grid": [                 // up to 9 rows of up to 9 cells
        [ { "type": "Entity|Goal|Obstacle|Location|Shift|Timepoint", ... }, null, ... ]
      ]
    }
  ]
}
  • You can start from the template above and only change words (labels, names, text).
  • Missing rows in grid are treated as empty; ONYX always builds a full 9d79 internally.
  • Extra fields are ignored safely; machines just need this core shape.
