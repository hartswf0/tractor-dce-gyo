LEGOS Grammar – Core Components
<Entity>
Any discrete noun or concept that exists (character, object, place, faction, idea).
Examples: <Agent-4>, <The Archive>, <Sticker Gallery>.
[Morphism]
Any verb, relationship, or transformation connecting entities.
Format: [verb] <entity A> → <entity B>.
Examples: [guides], [betrays], [protects], [misaligns_with].
<Goal>
A desired state or outcome held by an entity.
Examples: <Protect the Realm>, <Maintain AI Alignment>.
<Obstacle>
A blocker that prevents a goal.
Examples: <Spec Drift>, <Firewall>, <Public Distrust>.
[Shift]
A significant transition between states.
Examples: <AI Becomes Self-Aware>, <Oversight Committee Formed>.
<Location> / <Timepoint>
Spatial/temporal containers for events and entities.
Examples: <City of Bone>, <Digital Archive>, <Year 2027>.
📐 Every LEGOS sentence can be read as: <ENTITY> [MORPHISM] <ENTITY> in a <LOCATION> while pursuing <GOALS>, encountering <OBSTACLES>, and undergoing [SHIFTS] over time.
YAML Templates – Canonical LEGOS Output
Scene Template
LEGOS-GPT's primary output schema for any input turned into a scene or system.
scene: "<name>" description: "<short summary>" entities: - id: ... type: ... name: ... traits: [...] location: <location_id or label> goals: - id: ... name: ... owner: <entity_id> obstacles: - id: ... name: ... affects: <goal_id> shifts: - id: ... name: ... from: ... to: ... causes: ... relations: - [morphism] <entity_1_id> -> <entity_2_id> timeline: - id: ... description: ... scenes: [...]
System Template
A variant emphasizing title-level systems or worlds.
title: "<Name of Story/Scene/System>" description: "<One-sentence summary>" location: "<Where does it happen?>" entities: - id: ... type: ... name: ... traits: [...] location: <location_id> goals: - id: ... name: ... owner: <entity_id> obstacles: - id: ... name: ... affects: <goal_id> shifts: - id: ... name: ... causes: [<obstacle_id>] results_in: <goal_id or entity_state> relations: - [morphism] <entity_1_id> -> <entity_2_id> timeline: - id: ... description: "<Phase or year>" scenes: - id: ... description: "<Mini-event>" entities: [<entity_id>, ...]
LEGOS Grammar Cheat Sheet – Quick Reference
Core Components

<LOCATION> – spatial/temporal containers.
<ENTITY> – characters, objects, systems, ideas.
<GOAL> – desired outcomes for entities.
<OBSTACLE> – anything blocking goals.
[MORPHISM] – verbs/relations between entities.
[SHIFT] – major transitions in state/structure.
<TIMELINE> / <SCENE> – time-indexed sequences.

Use Cases – Where LEGOS-GPT Fits
Worldbuilding
Turn loose notes about a setting into reusable entities, locations, and timelines. Attach goals and obstacles per faction to drive campaigns or series bibles.
Story Decomposition
Take an existing story (novel, film, session log) and decompose it into LEGOS blocks to analyze pacing, structure, and character arcs.
Multi-Agent Simulations
Use goals, obstacles, and morphisms as state for agents in a simulation. Each tick, agents act to resolve obstacles and advance goals.
Adaptive Narratives
Drive branching stories or games from the LEGOS model: when a shift fires or a goal resolves, unlock new scenes or mechanics.
Concept Modeling
Express abstract domains (AI history, economics, romance, dreams) as entities, relations, and shifts to make them explorable and editable.
Step-by-Step – How to Use LEGOS-GPT
1CHOOSE AN INPUT
Decide what you want to model: a scene, a relationship, a whole world, or an abstract process. Feed LEGOS-GPT raw prose, bullet points, transcripts, or concept descriptions.
2ASK FOR A LEGOS MODEL
Prompt LEGOS-GPT with instructions like:
"You are LEGOS-GPT. Take the following input and emit a YAML LEGOS model using the scene template. Make entities, goals, obstacles, shifts, relations, and a small timeline."
The output will follow the YAML schemas shown above.
3REFINE THE BLOCKS
Ask follow-ups: split or merge entities, add missing goals, clarify obstacles, or propose alternative shifts. LEGOS-GPT can update the YAML while preserving IDs and structure.
4HOOK INTO ENGINES
Once stable, feed the YAML into your own tools: story engines, dashboards, agent simulators, or visualization layers. Because it is machine-parsable, the same model can drive many front-ends.
